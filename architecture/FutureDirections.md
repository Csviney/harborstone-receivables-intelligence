# Future directions

Living backlog, **not initial scope**. Promote work only when its value and missing inputs justify the complexity. Accepted scope changes belong in [DesignDecisions.md](DesignDecisions.md) and the authoritative guides.

| Direction | Value / prerequisite |
|---|---|
| Source refresh | Current AR rather than a static export. Requires actual APIs/export schedules, stable IDs, freshness expectations, and reconciliation; invalidate stale assessments. |
| Source-system links | Easier correction in the authoritative system. Requires verified URLs/IDs and permissions; never fabricate links or local overrides. |
| Controlled write-back | Correct supported issues once. Requires agreed ownership, approval, authorization, and audit rules. |
| Email/reply tracking | Less handoff friction. Requires real mailboxes, validated recipients, approvals, delivery handling, and demonstrated demand. Copy is not send. |
| Scheduled/durable execution | Less manual follow-up at scale. Requires cadence ownership, idempotency, monitoring, and a need for unattended work. |
| Outcome measurement | Test handling-time and working-capital improvements. Requires baseline/usage data; collection attribution also needs actual outreach and refreshed receipts. Association is not causation. |
| Broader financial insight | Profitability, cash forecasts, or closeout. Requires reconciled GL/cost mappings, budgets, remaining costs, disbursements, and documents currently missing. |
| Shared production use | Multiple staff and reliable service. Requires authentication, authorization, retention/provider policy, deployment, backup, concurrency, and ownership. |

The first expansion should address an observed bottleneck in the completed journey, not simply add AI or touch more tables.
